# Claude Code 与 Desktop

## 先保留已有保护

检查实际执行入口、原生程序、代理闸门、设置和对应进程；使用文件指纹比较保护是否被改动。用户已有正常工作的保护，不因本技能重新安装、重写或卸载。不要把“本机曾有”当成“别人机器也有”。

## Claude Code 代理配置

核对当前官方网络说明。支持标准 HTTP/HTTPS 代理环境变量；不要把远端 VLESS 地址或 SOCKS URL 当作 Code 原生支持的 HTTP 入口。

优先限定到 Claude 的启动器或用户 Claude settings，避免为了 Claude 修改全终端的联网行为。小写/大写代理变量需统一，检查 `NO_PROXY/no_proxy` 是否包含 `*`、Claude 域名或广泛例外。示例是已验证入口的 **占位方式**，不能把 LOCAL_PORT 原样写入：

```sh
HTTP_PROXY=http://127.0.0.1:LOCAL_PORT
HTTPS_PROXY=http://127.0.0.1:LOCAL_PORT
http_proxy=http://127.0.0.1:LOCAL_PORT
https_proxy=http://127.0.0.1:LOCAL_PORT
NO_PROXY=localhost,127.0.0.1,::1
no_proxy=localhost,127.0.0.1,::1
```

保留用户其他设置与账号提供方。配置更新后重新启动目标会话，检查新进程使用的入口。环境变量是应用遵守的配置，不是网络强制隔离；子工具可能不支持它，系统打开的浏览器也不自动继承限制。

## 需要严格防直连时

以三层实现为参考，现场适配后才声称受保护：

1. **应用配置**：明确代理与有限的本地例外，覆盖冲突变量。
2. **启动闸门**：核对本机监听进程属于预期代理、TCP 可连接、经代理的未认证 HTTPS 请求与证书校验成功。失败停止启动，不降级直连。只看到端口开放不够。
3. **运行时网络限制**：让 Claude 与其子进程只能访问预期回环代理端口，其他外连失败。已有系统级机制优先；没有可用机制时如实报告仅完成前两层。

macOS 历史方案曾使用独立 wrapper 和 `sandbox-exec`，但这不是所有 macOS/Claude 版本的兼容保证，也不是厂商承诺的防火墙。检查工具可用性并在隔离测试进程里验证策略后才能用于启动；工具缺失或策略失败必须停止，不能悄悄降级。此技能不附带未经新主机验证的“一键强隔离”程序。

保留独立 wrapper 路径，避免与原生安装器/自动更新目标重叠，解析原生目标时防止递归调用 wrapper。运行时只允许回环端口仍需确保本机代理把 Claude 域名送到预期节点，不会在上游失败时直连。

必要检查：

- `command -v claude` 指向预期入口；新会话和原生路径分清。
- 模拟代理进程缺失、端口拒绝、上游失败时不调用原生程序；模拟结果与真实故障结果分列。
- 在同样限制下的测试进程：经代理请求成功，直接 TCP、UDP 和子进程直连被拒绝；同时测试是否误伤需要的本地工具。
- 未认证请求返回 HTTP 401 可能是正常网络证明，不能写成模型请求成功；模型测试另经用户允许，额度不足就停止。
- 更新 Claude/系统/代理后，复核入口、监听者和上述关键行为；不要只看版本号。

## Desktop 与登录

Code 的 shell 变量或 wrapper 不会自动保护 Claude Desktop、IDE 自启进程、外部浏览器。分别测试它们的连接。Desktop 版本可能有自身网络管理行为，以官方说明、当前设置与实际请求为准。

单独区分：登录页面加载、OAuth 回调、账号认证、内容资源加载、真实模型响应、项目目录权限。登录正常不保证动态内容域可达；代理连接正常不保证账号有额度。用户要求使用前准备时，可停在网络验收；未运行模型就标记未测。
