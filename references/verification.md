# 验收记录与故障判断

每项记录入口/配置文件、时间、预期、观察、结论。结论仅用“通过/失败/未测/不适用”，不要从上一层推断下一层。

| 层级 | 最小证据 | 不能推出 |
|---|---|---|
| 本地清理 | 授权清单与处理后回读，保留/未知项 | 硬件身份重置、云端删除 |
| 配置保存 | 新旧差异、可回退副本、无非预期修改 | 配置正在生效 |
| 规则加载与匹配 | 当前启用配置 + 应用内每个目标的匹配结果 | 每个真实请求路线、目标服务可用 |
| 真实路线 | 同一应用的连接日志/出口查询，必要时限定抓包 | DNS/WebRTC 均无旁路 |
| DNS | 同一浏览器两轮结果 + 主/备用路径核对 | 全应用、断线回退均已验证 |
| WebRTC | 测试实际完成、候选地址与设置生效记录 | 其他 Profile 或设备也通过 |
| IPv6 | 区分本机、节点和解析器地址 | IPv4 固定等于双栈固定 |
| 防直连 | 正常可用、故障时拒绝、恢复复验，注明模拟与真实 | 未经启动器启动的程序也被保护 |
| Claude 功能 | 登录/内容/模型响应各自结果 | 账号未来不受限制 |

## 常见误判

- **看见 TUN 就断言走国外节点**：TUN 是客户端处理流量的入口，随后仍可能 DIRECT。查目标连接的策略和实际出站。
- **DIRECT 已命中，SSH 仍超时**：规则选择与端口可达分开。可用有限的普通 socket 与绑定物理网卡的单连接对照；绑定网卡不等于完全排除所有系统过滤。若直连也失败，优先定位目标端口/链路，不重复添加同一规则。本技能到此提供证据，不改服务器。
- **网页延迟高就认定代理绕行**：解析、握手、缓存、资源加载都影响时间；读取实际请求主机，找路由证据。
- **curl 经代理成功就说浏览器通过**：curl 不验证浏览器 DNS、WebRTC 或系统登录窗口。
- **BrowserLeaks 好结果来自网页抓取服务**：该结果是抓取服务器的网络，不是用户电脑。必须在实际本机浏览器运行。
- **No Leak/代理 IP 没变就说账号安全**：测试只描述当前网络；IP 归属、代理识别、账号状态是不同问题。
- **配置有回退键就声称故障不直连**：当前正常路径、备用上游、真正故障与恢复必须分列。

## 分享与交付

本机保留敏感回退配置；公开版本只列规则片段、已脱敏结果和待办。不要分享整个 Shadowrocket 导出、浏览器数据库、Claude 配置、钥匙串内容、节点列表或历史命令。

交付示例：

“Claude 浏览器当前出口与 DNS/WebRTC 测试通过，国内指定域名匹配直连；Code 只完成代理配置，运行时限制未验收；云端账号关联未处理。建议先用已验收浏览器入口，补齐 Code 故障测试后再使用该入口。回退为原配置副本。”

这只是结构示例，不可当成执行结果照抄。
