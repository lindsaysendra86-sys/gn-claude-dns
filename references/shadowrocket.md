# Shadowrocket DNS 与分流

## 基线与改动边界

在 UI 确认当前 **配置模式、启用配置、所选节点、策略组与回退行为**，导出/复制启用配置后再改。保存文件名不代表已加载。端口以实际监听为准，HTTP 本地入口与远端 VLESS/SOCKS 端口不能互换。只监听回环地址；本技能不要求开放局域网代理。

历史 macOS 经验使用过 SQLite `config` 表和二进制 plist，但不同版本可能变化。优先应用 UI/导入导出；不要默认直接写运行中的数据库。读取时只读、按需输出，导出配置含节点秘密，不能放进公开附件。自动订阅/模块可能覆盖本地编辑，需查清覆盖源，保留必要更新机制。

## DNS（把域名解析成地址的服务）

以下是历史 macOS Shadowrocket 环境接受并使用过的 **合并示例**，不是所有版本保证适用的模板：

```ini
[General]
dns-server = https://1.1.1.1/dns-query#proxy
fallback-dns-server = https://1.0.0.1/dns-query#proxy
dns-direct-system = false
udp-policy-not-supported-behaviour = REJECT
```

- DoH 是经 HTTPS 加密的 DNS；`#proxy` 意图是让解析服务器连接也经过代理。只填公共 DNS 地址、只启用加密或只看到虚拟 DNS 地址，都不能证明查询走预期出口。
- 合并时更新原键，不能保留冲突的重复项；主/备用 DNS、模块、按域名覆写、系统回退、浏览器“安全 DNS”分别核对。当前版本若有额外系统回退开关，应按内置说明核对，不能因为片段没有该键就假定回退已禁用。
- 先验证主和备用上游经当前代理可达，再加载。代理节点若以域名连接，需要核对其启动解析路径，避免 DNS 依赖代理、代理又依赖 DNS 的循环。确有启动例外时限定到节点启动并如实记录。
- 统一让 DNS 经代理可能影响国内网站解析延迟与资源节点选择；目标为 Claude 隔离时可用已验证的应用专用方案。不得为了低延迟静默恢复运营商 DNS。
- `REJECT` 会让不支持转发的 UDP 请求失败，可能影响语音等功能；需现场确认该键语义与需求。它不是 WebRTC 已防泄露的证据。
- UI 接受配置、成功解析与备用路径失败时不直连是三个证据层。无法做故障测试时明确“当前正常路径通过，失败回退未验证”。

## Claude 分流

[核心片段](../assets/claude-rules.conf)覆盖六组官方主域及子域。核查优先顺序，避免前面的直连规则、模块或其他优先规则抢先匹配。不能只在最后追加到 `FINAL` 后面。保留用户现有规则，先检查差异再激活。

`PROXY` 通常指当前选中代理，但可能被用户策略组重定义；必须现场确认。关闭或调整会让 Claude 回退到 DIRECT/其他出口的组行为。固定出口需求应记录预期节点并验证实际公网出口；人工换节点后要复验。

登录依赖按实际方式追加：Google 登录的 `accounts.google.com`、`oauth2.googleapis.com`、`openidconnect.googleapis.com`、`www.googleapis.com` 等；企业单点登录使用现场身份服务。动态内容的第三方字体/脚本依赖见官方网络文档。只把确需访问的主机路由到代理，不擅自启用遥测或移除用户已设的阻断。

第三方域名规则影响所有调用它的应用，不能声称只对 Claude 生效。`registry.npmjs.org`、CDN/字体等应按需求选，不强制整机走代理。

## 国内网站直连

按用户要直连的网站合并 [国内片段](../assets/domestic-direct-rules.conf)。该片段是常用主站和资源覆盖的起点，不代表全站所有域名。已有等效规则不重复添加；存在用户明确代理/阻断策略时先解释冲突。

排查测试页时读取它的真实请求地址：例如“抖音”可能请求 `lf3-static.bytednsdoc.com`，“飞书”可能请求 `lf-package-cn.feishucdn.com`。只测 `douyin.com`/`feishu.cn` 会漏掉这一层。页面更新后重新确认，不永久绑定旧测试地址。

不默认添加全部 `.cn` 直连、不改变现有 FINAL/国内 IP 兜底策略，不随模板携带个人服务器 IP。若用户单独要求 IP 规则，按指定范围另行核验；该操作不包含云端运维。

## 加载、验证、回退

1. 比较新旧配置，只出现本次拟议改动，既有规则/认证/节点保留。
2. 用应用的“使用配置”或当前等价入口加载，不默认关闭整个隧道。
3. 用应用内测试确认：Claude 主站/API/内容域为预期代理；用户要求直连的每个实际目标为 DIRECT。
4. 再通过同一客户端真实请求与连接日志确认路径。操作系统路由经过 TUN（虚拟网卡）只说明先由客户端处理，不能直接推出“走了代理节点”。规则匹配也不能代替这一步。
5. 失败时切回原配置并验证已恢复。不得在远程不可控的情况下整机断网。
