# 本地状态、历史与缓存

## 清理目标和范围

用户说“清除设备标识”时，将可交付目标说准确：移除已识别的 **Claude 应用生成的本地安装/登录状态**，同时按授权清理历史和缓存。硬件序列号、系统设备身份、平台保存的设备登记、云端会话及账号关联不在本地删除的证明范围内。不存在能可靠保证“抹掉所有 Claude 痕迹”的通用文件列表。

清理会登出、丢失本地会话或偏好。先给清单：目标、作用、处理方式、可否恢复、保留内容、当前占用进程。不因用户只问网络问题就清理本地数据。用户要保留历史时，选择只清缓存/旧网络设置；可建议独立浏览器配置文件隔离新环境，但不将它描述为身份重置。

## 发现位置（候选，不是直接删除清单）

| 对象 | macOS 常见位置或入口 | 处理注意 |
|---|---|---|
| Claude Desktop | `~/Library/Application Support/Claude`；应用 bundle ID 对应的 Caches、Preferences、WebKit、Saved Application State、Logs | 先验证当前版本实际占用；会话、设置与认证可能混存。不要把整个 Library 或所有 Electron 目录当目标 |
| Claude Code | `~/.claude`、`~/.claude.json`、`CLAUDE_CONFIG_DIR` 指定目录 | `~/.claude` 含设置、规则、技能、插件、项目历史等，不能一刀切。安装目录与数据目录分开 |
| 安装程序/旧版本 | `~/.local/bin/claude`、`~/.local/share/claude/versions`、实际 npm/Homebrew 安装位置 | 仅用户要求卸载/重装时处理，不因清缓存删除可用二进制 |
| 浏览器 | 用户指定 Profile 的站点数据、Cookie、历史、下载列表、扩展存储 | Chrome、Safari、Edge、独立环境分别核对。普通 Chrome 清理不会清掉其他环境 |
| 钥匙串 | 当前 Claude 应用确实使用的服务项，如候选 `Claude Safe Storage`、`Claude Code-credentials` | 仅查名称和存在性，不输出值；先确认归属，不清整个钥匙串 |
| 第三方接口覆盖 | shell、用户/项目 Claude settings、`apiKeyHelper`、现有切换工具 | 只清用户确认废弃的配置；切换工具可能同时保存其他应用设置，不整体卸载 |
| 终端历史与备份 | 当前 shell 的 history/session 文件、已定位的 Claude 备份 | 仅用户明确要求时定向清理；不能仅按单词 claude 删除所有命令，更不能删除系统备份 |

进程发现只输出名称/可执行文件路径，不批量打印完整命令行，避免认证参数进入报告。可用 `ps -axo pid=,comm=`、只读目录清单、文件类型与权限发现；不递归输出全部内容。

## 可执行步骤

1. 识别 Desktop、Code、浏览器各自是否在使用；清理前正常退出目标应用。保持代理和当前操作通道可用。无法关闭时先完成无关准备，将该部分标记待处理。
2. 优先使用产品的退出登录与站点数据管理界面。浏览器按实际站点边界处理 `claude.ai`、`claude.com`、`anthropic.com` 及确认相关内容域；不清全浏览器、不默认清 Google 登录或其他站点。历史记录与 Cookie 是两类对象，分别核对。
3. 对混合 JSON 设置：只移除有证据确认属于授权范围的字段，保留其他键。不要写入猜测的新 `userID`/device ID。应用重新生成配置是正常行为，不证明服务端认定为新设备。
4. 文件操作按已确认的绝对路径执行，拒绝越界符号链接；能隔离/备份的先限定目录回退，要求永久删除时按当次授权执行。若保留了备份或移到废纸篓，报告“已从活动位置移出”，不能称已不可恢复地清除。
5. 浏览器数据库仍被占用时不直接修改；优先用应用 UI。若确需离线精确处理，必须先退出目标 Profile、检查数据库一致性和关联表，再实施。无法访问的 Profile/系统登录窗口明确列为未检查。
6. 重新核对目标目录、对应钥匙串项和站点数据。重装仅走当前官方安装来源并核对签名/版本。运行认证状态检查只记录已登录与否，不记录令牌、邮箱和完整账号标识。

## 授权来源检查

查看以下键是否存在即可，公开输出不要显示值：`ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL`、`apiKeyHelper`、模型映射、第三方 provider 配置。用户使用第三方提供方（实际接收模型请求的服务）时，不自动改回官方；只有用户要求迁移才清理冲突项。

检查当前 shell、新登录 shell、运行中的应用、launchd、用户与项目 settings 的实际来源。单个文件没有密钥，不等于所有入口都没有覆盖项。环境变量变更通常不影响已启动会话。

## 清理验收

记录“检查过哪些位置/删除或移出什么/保留什么/未访问什么”。恢复应用后新生成的正常缓存可存在。未逐个核对的历史浏览器、隐藏登录窗口、同步数据、系统备份和服务端历史都不宣称已清理。
